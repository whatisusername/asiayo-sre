# 情境實戰測驗 02

- 如果因為 timeout 的問題影響到使用者，會先確認是否能讓有問題的機器先停止接收流量，再進一步進行排查
- 因為服務由多台機器組成，目前只有其中一台經常發生 timeout，會先確認問題是否真的集中在該機器，再比較該機器與其他正常機器的 環境變數、metrics、流量、設定與版本差異等
- 可能都把流量導向該台機器了，確認該機器是否有資源瓶頸，CPU、Memory、Disk I/O、網路等
- 查看服務的 metrics、log 和 trace，確認 timeout 發生時服務正在執行什麼操作，再繼續往下查
- 雖然只有單一機器發生問題，但這裡不會完全排除網路因素，如果該機器位於不同 AZ，需要確認問題是否和特定 AZ 有關，也檢查同樣 AZ 的其他資源是否有類似現象
